# fs 设计

- 日期：2026-10-04
- 状态：已实现（POSIX 侧验证过，Windows 侧从未编译）
- 取代 [预期接口](2026-10-03-module-interfaces.md) 第 5 节。`fs::watcher` / `fs::poller` 仍在第三程，不在本文范围。

## 1. 范围

C++11 没有 `std::filesystem`，这是缺失感最强的一块。做：路径的纯字符串操作、查询、整文件读写、目录与文件操作、遍历。

**`path` 不拆成独立头文件。** coost 单列了 `path.h`（114 行），曾考虑跟进；但路径部分只有八个函数，而它们和 `exists` / `read_file` 总是一起用，拆开反而要 include 两个头文件。等路径操作长到十几个再说。

**不做**：符号链接的创建与读取、权限的读写、硬链接、文件锁、内存映射、递归遍历（`list_directory` 只看一层，要递归自己套）、`std::filesystem` 的 `path` 类型。都没有消费者。

## 2. 三条贯穿全模块的约定

### 2.1 路径是 UTF-8 的 std::string，没有 path 类型

代价是路径和普通字符串混用时编译器发现不了，好处是每个接口少一层转换。Windows 下库内部转成 UTF-16 调 `W` 系列 API。

输入接受 `'/'` 和 `'\\'`，输出用平台原生分隔符。**POSIX 上 `'\\'` 不算分隔符**——它在 POSIX 上是合法的文件名字符，当成分隔符会把 `"a\\b"` 这个合法文件名切开。

### 2.2 符号链接默认跟随，递归删除不跟随

| 操作 | 符号链接 | 为什么 |
| --- | --- | --- |
| `exists` / `is_file` / `is_directory` / `file_size` / `last_write_time` | **跟随**（`stat`） | 这些问的是「那里有个能打开的文件吗」，不是「那里有个链接吗」 |
| `remove_directory(recursive::yes)` | **不跟随**（`lstat`） | 跟进去会删掉链接指向的**别处**内容。那个代价太大，而且是不可逆的 |

Windows 侧用 `FILE_ATTRIBUTE_REPARSE_POINT` 判断，语义相同。

### 2.3 每个函数只做名字说的那件事

目标存储包含 HDD 和网络挂载。一次 `stat` 在本地缓存热时 ~475 ns，冷的 HDD 上 5–10 ms，NFS 上 0.2–1 ms（见 `CLAUDE.md`「性能与占用」）。所以：

- `exists` 不顺手判断是文件还是目录。需要两个答案时直接用 `is_file` / `is_directory`，别连着问两次——在网络盘上那是两次往返。头文件里写明了这一点。
- 遍历时**只在 `d_type` 返回 `DT_UNKNOWN` 时才退回 `stat`**。有 `d_type` 的文件系统（ext4、XFS）一次系统调用就够。
- 这条约定的反面教材是 `fs::watcher` 曾经设计的隐式 `stat`，已去掉（见路线图 4.5）。

## 3. 关键决定

### 3.1 遍历：模板回调 + 不透明句柄

冲突是：回调式要么用 `std::function`（违背「慎用有隐性开销的设施」），要么把实现放头文件（违背「公共头文件不含平台头」）。

解法是 `detail::directory_handle`：头文件里是完整类型，但**只有一个 `void*` 成员**，三个方法（`open` / `next` / 析构）全在 `fs_posix.cpp` / `fs_win.cpp` 里实现。头文件里的模板只负责循环和调回调：

```cpp
template <typename F>
result<void> list_directory(string_view path, F&& callback) {
    result<detail::directory_handle> opened = detail::directory_handle::open(path);
    if (opened.is_err()) return std::move(opened).error();
    detail::directory_handle handle = std::move(opened).value();
    entry current;
    while (handle.next(current.name, current.is_directory)) {
        if (!callback(static_cast<const entry&>(current))) break;
    }
    return result<void>();
}
```

所以公共头文件不含 `<dirent.h>` / `<windows.h>`，而回调仍然是零开销的。

`DT_UNKNOWN` 的回退用 **`fstatat(dirfd(dir), name, ...)`**，不是拼完整路径再 `stat`：句柄不存目录路径，而且这样不受遍历期间当前目录被改动的影响。第一版写的是 `stat(item->d_name)`，那是相对于当前目录的，错的。

一次取全的 `list_directory` **排序**，这样输出可重现（`readdir` 的顺序由文件系统决定，ext4 上是哈希序）。回调版本**不排序**，头文件里写明了。

### 3.1b 递归的逻辑只有一份，平台只提供三个单级原语

第一版把 `create_directory(recursive::yes)` 和 `remove_directory(recursive::yes)` 的循环**在两个平台文件里各写了一遍**，结构一样，只差「用哪个 mkdir」和「怎么判断符号链接」。复审时提到 `fs.cpp` 里，平台只留三个原语：

```cpp
namespace detail {
result<void> make_directory(string_view path);            // 建一级，已存在返回 already_exists
bool is_directory_not_link(string_view path) noexcept;    // 决定递归删除要不要进去
result<void> remove_empty_directory(string_view path);
}
```

两个收益：**那两段容易出错的循环不会有两份互相漂移的副本**；而且 `fs_win.cpp` 少了 46 行——那是从未被任何机器编译过的代码，减少它本身就是降低风险。

Windows 上「`C:` 这一级不能创建」用已有的 `root_name_length` 在共享代码里判断，不需要在平台文件里另写一套盘符逻辑。

**一处要小心的地方**：`make_directory` 故意**不自己判断已存在的是不是目录**——那要多一次 `stat`，而递归创建时每级都多一次，在网络盘上是几毫秒。所以 `already_exists` 原样返回，由调用方在最后查一次。

### 3.2 normalize 不访问磁盘

消掉 `"."` 和 `".."`、合并重复分隔符，但不解析符号链接。所以 `"a/b/../c"` 变成 `"a/c"` **即使 `b` 是指向别处的符号链接**——那种情况下两者不等价。

这是有意的：`normalize` 是纯字符串操作，零系统调用，在网络盘上免费。要正确处理符号链接用 `absolute`（它至少读一次当前目录）。头文件里写明了这个区别。

边界：`normalize("")` 和 `normalize("a/..")` 都是 `"."`；绝对路径的 `"/.."` 就是 `"/"`；相对路径的 `"../a"` 消不掉，保持 `"../a"`。

### 3.3 create_directory 幂等，但同名文件挡住时报错

目标已存在**且是目录**时返回成功——「确保这个目录存在」是真实需求，而让调用方先 `is_directory` 再创建既多一次系统调用又有竞态。

已存在但是**文件**时报 `already_exists`，不假装成功。

### 3.4 copy_file 默认不覆盖

`overwrite::no` 是默认，覆盖必须显式写 `overwrite::yes`。这是「难以误用」：丢数据的那个方向要多打几个字。

POSIX 侧复制后把权限位一起 `chmod` 过去，否则复制可执行文件会丢掉执行位。

### 3.5 错误原因必须能区分

`errno` / `GetLastError` 映射到 `error_kind`，因为**调用方要据此决定行为**：

| `error_kind` | POSIX | Windows |
| --- | --- | --- |
| `not_found` | `ENOENT` `ENOTDIR` | `ERROR_FILE_NOT_FOUND` `ERROR_PATH_NOT_FOUND` `ERROR_INVALID_DRIVE` |
| `permission_denied` | `EACCES` `EPERM` `EROFS` | `ERROR_ACCESS_DENIED` `ERROR_SHARING_VIOLATION` `ERROR_WRITE_PROTECT` |
| `already_exists` | `EEXIST` `ENOTEMPTY` | `ERROR_FILE_EXISTS` `ERROR_ALREADY_EXISTS` `ERROR_DIR_NOT_EMPTY` |
| `invalid_argument` | `ENAMETOOLONG` `EINVAL` | `ERROR_FILENAME_EXCED_RANGE` `ERROR_INVALID_NAME` |
| `unsupported` | `EISDIR` | `ERROR_NOT_SUPPORTED` |
| `io` | 其他 | 其他 |

「配置文件不存在就用默认值、权限不足就报错退出」是典型的分支，所以这个映射不能含糊。消息里一律带路径，否则跨层传上去就不知道是哪个文件。

### 3.6 读写一律二进制

不做换行转换：读到的就是磁盘上的字节，内嵌 `'\0'` 也保留。Windows 上用 `"rb"` / `"wb"`。测试里用 `"a\0b\r\nc"` 钉住了。

`read_file` 先 `fstat` 问大小好一次读完；拿不到大小（管道、`/proc`）就退回 8 KB 分块读。读的过程中文件变短了不算错，只是结果短一些。

## 4. 实现验证

环境 Linux / GCC 14.2，`-Wall -Wextra -Wpedantic -Werror`，全程零警告。

### 4.1 构建与测试

119 个测试通过（新增 14 个）。磁盘相关的测试每个自己在 `temp_directory()` 下建一个 `culib_fs_test_<名字>` 目录，用 RAII 保证结束时整棵删掉，并且**开头先删一次**（上次跑崩了留下的残骸）。

覆盖：路径的八个函数（含 `".bashrc"`、`"/a/b/"`、`""` 这些边界）、`normalize` 的九种形状、`is_absolute` 的平台分支、读写（覆盖 / 追加 / 空文件 / 二进制 / `out` 版本）、错误种类的区分、存在性与类型查询、`create_directory` 的幂等与两种阻挡、删除的安全阀（非递归删非空目录必须失败）、复制的默认不覆盖、20 万字节文件跨块边界的复制、遍历的三种用法（取全 / 回调 / 提前停）、空目录、中文路径、当前目录与临时目录。

头文件单独 `-fsyntax-only` 通过。`examples/fs.cpp` 可编译运行。

### 4.2 顺手发现的一个 result 缺陷

写示例时第一次真正用 `value_or`，撞上 `value_or({})` 编译不过：花括号初始化列表推导不出模板参数 `U`，报错是「couldn't deduce template parameter 'U'」。

**没有改 `result`。** 试过加一个非模板的 `T value_or(T)` 重载，实测它能让 `{}` 工作且不引入歧义，但代价是 `value_or(某个左值)` 会落到非模板版本上、**无条件多拷一次 fallback**（按值传参），而模板版本只在错误分支才转换。为了让 `{}` 能写而拖慢常见写法不值得。而且 `std::optional::value_or` 有完全一样的限制，匹配标准库才是「看名字就会用」。

改成在 `result.h` 里写明这件事——报错信息看不出原因，下个人会卡住。

### 4.3 没覆盖

- **`src/fs_win.cpp` 已经编译并跑过测试了**（MinGW-w64 + wine，349 行第一次过编译器，零警告；134 个测试全通过）。办法见 `CLAUDE.md`「约定与机制」。**但 MSVC 仍未验证**——头文件、`__declspec`、警告集都和 MinGW 不同。
- 第一次在 Windows 上跑抓到的唯一一个真问题是**测试写错了**而不是代码错：`fs_path.joins` 用一个把所有 `/` 换成 `\` 的辅助函数去造期望值，而 `join` 只为自己插入的那一个分隔符用原生字符。顺带暴露了 `is_absolute("/b")` 在 Windows 上是 `false`（那只是「当前盘的根」，不是完整的绝对路径），所以 `join("/a", "/b")` 会把 `/b` 当相对路径接上去。两者都写进了 [API 指南](../../api-guide.md)。
- **macOS 没跑过。** POSIX 代码应该可移植，但 `fstatat` 的可用性、`d_type` 在 APFS 上的行为都没实测过。
- **符号链接的行为一条都没测过**：没有创建符号链接的 API（不在范围内），所以测试里造不出符号链接。「递归删除不跟进符号链接」是按 `lstat` 写的，逻辑上对，但没有测试钉住。**这是本模块最该补的一个测试**，等 `os` 或某处提供了创建符号链接的手段再补。
- **权限错误没测过**：要以非 root 身份访问一个不可读的文件，而测试环境是 root。`permission_denied` 这一支从未执行。
- 跨文件系统的 `rename`（POSIX 上会 `EXDEV`）没测过，头文件里写明了这时要自己 copy + remove。
- 超长路径（> 256 字节，走 `c_path` 的堆分支）、以及 Windows 的 `MAX_PATH` 限制都没测过。
- 并发：两个进程同时写同一个文件的行为未定义，没有文件锁。
