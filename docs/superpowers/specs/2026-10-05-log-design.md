# log：四个待定项的答案

- 日期：2026-10-05
- 状态：**已实现**。路线图第二程第 10 项。
- 前置：[预期接口](2026-10-03-module-interfaces.md) 第 10 节给了形状和**四个「要定的事」**，本文逐条定掉。依赖 `time` + `term` + `fs` + `strings`，四个都已完成。

## 1. 已有设计留的四个问题

预期接口第 10 节末尾写着：

> **要定的事**：格式化用什么（取决于 `strings` 的格式化最后缩成什么样）；是否异步（异步要队列和后台线程，依赖 `thread`，但能避免日志拖慢业务线程）；轮转的触发与命名规则；多线程写同一个 sink 怎么加锁。

逐条。

### 1.1 格式化：流式，不是 printf 式

`strings` 的格式化最后**没做**（路线图第一程把它切出去了），所以「取决于它」这条前提不成立，得自己选。

| | printf 式 `LOG_INFO("port=%d", port)` | 流式 `LOG_INFO << "port=" << port` |
| --- | --- | --- |
| 类型安全 | **没有**。格式串和参数对不上是运行期崩溃，MSVC 上还没有 `__attribute__((format))` 那种检查 | 有，编译期就对上了 |
| 能不能用在自己的类型上 | 不能，除非先转成字符串 | **能**，有 `operator<<` 就行 |
| 新设施 | 要自己做格式化 | 一个都不要 |

取流式。决定性的是第一条：**格式串错配是运行期崩溃**，而开发约定里「难以误用」是硬要求。附带的好处是 `term` 的带色值、`timestamp`、任何用户类型都直接能用。

代价是一个 `std::ostream`。为了不每行分配，消息写进**调用方栈上的一块固定缓冲**（`line_capacity`，1 KB）加一个写它的 `streambuf`，超长就截断。日志丢几个字比让业务路径去分配内存好。

**没用线程局部的复用缓冲**（那样也不分配），因为那条路不可重入：`LOG_INFO << f()` 而 `f()` 里面又写了日志，两次就会用同一块缓冲、互相踩。放在栈上天然每层一份。

### 1.2 异步：不做

异步要一个队列加一根后台线程（或者一根协程），还要回答「队列满了怎么办」「进程崩的时候队列里的丢不丢」「多个 sink 的顺序」。

**不做，因为没有消费者量出日志是瓶颈。** 现在一行日志 1592 ns（见第 3 节），一个每秒写一千行的服务器花在日志上的是 1.6 毫秒，占一个核的 0.16%。

**什么条件下重开**：量出某个真实负载里日志占比显著。那时候要连「崩了丢不丢」一起定——现在同步写的那条性质（见 1.4）会因为异步而失去，不能不声不响地换掉。

### 1.3 轮转：数字后缀，写完一行才判断

`add_file_sink(path, max_bytes, keep_files)`，`max_bytes` 为 0 就不轮转。

超过上限时：先关掉当前文件，`path.<keep_files>` 删掉，`path.<n>` 依次改名成 `path.<n+1>`，`path` 改名成 `path.1`，再重新打开 `path`。

- **数字后缀不带时间戳。** 时间戳命名（`app-2026-10-05.log`）要回答「按天还是按小时」「时区用哪个」「同一天写满了怎么办」，而数字后缀没有任何自由度。
- **写完一行才判断**，不是写之前。这样一行永远不会被切成两半分在两个文件里。
- 改名失败（别人占着、权限不够）不报错也不杀进程：重新打开失败就之后不写了。**不该为日志杀掉服务器**，这和栈分配失败那条是同一个取舍。

### 1.4 加锁：`std::mutex`，不是 `wavvix::mutex`

sink 是**进程全局**的，多个 vCPU 会写同一个，而协程锁只在一个 vCPU 内部有效（`culib/sync.h` 开头那段）。所以只能用线程锁。

那一小段会真的挡住 vCPU。能接受，因为：

- 锁里面只有「把拼好的一行交给系统调用」，**格式化在锁外面**（在调用方栈上）；
- 所以也就不会出现半行和半行交错——这正是「整行在栈上拼好再交出去」换来的。

**文件那一路没有用户态缓冲**：每行一次 `write`。进程崩掉时已经写出的行都在，而那是日志最要紧的性质之一。代价是一行一个系统调用（340 ns，见第 3 节）。

## 2. 两处和已有设计不同

| 已有设计 | 实际 | 为什么 |
| --- | --- | --- |
| `WAVVIX_LOG_INFO(...)`（带括号的可变参数） | `LOG_INFO << ...`（不带括号） | 跟着 1.1 的流式走。不带括号读起来就是一条流语句，而且 `if (x) LOG_INFO << "y"; else ...` 的 `else` 绑定是对的（宏展开成一个最多跑一次的 `for`，所以是**一条**语句） |
| `add_console_sink(bool colored = true)` | `add_console_sink()` | 开发约定说「用 `enum class` 代替 bool 开关」，而这个开关**根本不需要存在**：上不上色由 `term` 自己判断（终端 / `NO_COLOR` / `TERM`），要强制关就 `term::set_color_mode(never)`。少一个参数，少一处「每次都要先想一下」 |

另外两条是补充而不是改动：

- **不配任何 sink 时自动有一个 stderr 输出**（第一次写日志时才建，所以 `main` 之前不跑代码）。一行配置都不写就能用，而「写了日志却什么都没出来」是「意外」。`clear_sinks()` 之后**不会**再自动补——那是明确表示不要输出。
- **`fatal` 不 abort。** glog 的 `LOG(FATAL)` 会，但一句日志顺手把进程杀掉是「意外」；要优雅退出用 `culib/os.h` 的停止标志。

## 3. 量到的数（GCC 14.2 `-O2`，同一次运行）

| | 耗时 |
| --- | --- |
| 一整行日志（文件 sink，含时间戳、级别、文件行号、一次 `write`） | **1592 ns** |
| 其中时间戳格式化（`format_time` 写缓冲区的那个重载） | 75 ns（**4.7%**） |
| 级别不够，整句跳过 | **1.5 ns** |
| 对照：`fs::append_file` 每行开关一次文件 | 2613 ns（只是那一次写文件，不含日志其余部分） |
| 对照：常开句柄只 `write` | 340 ns |

三个结论：

1. **1.5 ns 那行就是宏存在的全部理由。** 级别不够时参数一个都不求值，所以 `LOG_DEBUG << expensive()` 在 info 级别下是自由的。有一条测试直接数 `expensive()` 被调了几次。
2. **`fs` 必须补一个常开句柄。** `append_file` 每行开关一次是 2613 ns 对 340 ns，**7.7 倍**；而在 HDD 或网络盘上 `open` 和 `close` 各要一次往返，差距是数量级的（开发约定「性能与占用」里那张 `stat` 的表）。所以这一期顺带给 `fs` 加了 `output_file`——**和 IOCP 逼出 `io_engine_adopt` 是同一回事**：一个模块落地时发现下层缺一块。
3. **`time` 留的那个待定项有答案了，是「不需要」。** `time.h` 里写着「本地时间没有写缓冲区的重载……等 `log` 落地、量出来真需要再加」。量完是 4.7%，为不到 5% 加一个接口和一份「上一秒拆好的字段」状态不划算。结论回填进了 `time.h`，带重开条件。

## 4. 实现验证

| 平台 / 工具链 | 结果 |
| --- | --- |
| Linux x86_64，GCC 14.2 / clang 19，debug / release | **251 个测试通过**，零警告 |
| MinGW-w64 x86_64 + wine | 248 个通过，零警告 |
| MinGW-w64 i686 | 编译链接通过 |
| ASan + UBSan，`detect_leaks=1` | 新增 12 条干净 |

新增 12 条，九条给 `log`、三条给 `fs::output_file`。都走**文件 sink 再读回来比对**：控制台那一路去的是 stderr，测试里没法干净截获，而两条路共用同一段「要不要写、写什么」的逻辑。

值得点名的三条：

- `does_not_evaluate_the_arguments_below_the_level`：数 `expensive()` 的调用次数，0 然后 1。**这条是 1.1 那个决定的全部依据。**
- `truncates_a_line_that_is_too_long_instead_of_allocating`：写三倍 `line_capacity` 的一行，结果还是一行、确实短了、前面那部分还在。
- `rotates_the_file_when_it_gets_too_big`：上限 200 字节、留 2 个，写 40 行之后 `.1` 和 `.2` 在、`.3` 不在。

`examples/log.cpp` 五段。**原来有第六段在示例里计时，删掉了**——开发约定写着基准测试不属于 `examples/`（那条是 `examples/time.cpp` 踩出来的），而且它确实会骗人：示例跑在什么优化级别上不由它决定，同一行代码 `-O2` 下 1.5 ns、不开优化 11.6 ns，差八倍。

## 5. 没做什么

- **异步**：见 1.2。
- **结构化日志**（键值对、JSON 行）：没有消费者，而且 JSON 要回答转义和嵌套，那是配置文件那一期砍掉 json 的同一个理由。
- **按级别分文件**：一个 sink 一个级别阈值。现在级别是全局的。**什么条件下加**：出现「error 单独一个文件」的真实需求。
- **`syslog` / Windows 事件日志**：三个目标场景里都没有消费者。
- **压缩旧文件**：要第三方库（zlib），而「零第三方依赖」是硬约束。
