# flag 设计

- 日期：2026-10-04
- 状态：已实现
- 取代 [预期接口](2026-10-03-module-interfaces.md) 第 3 节，以及 `2026-10-02-stopwatch-and-test-slimming-design.md` 6.1 的需求描述。

## 1. 前提：选项是全局对象

```cpp
flag::int64  port("port", 8080, "监听端口", {"p"});
flag::string input("input", flag::required, "输入文件", {"i"});

int main(int argc, char* argv[]) {
    flag::init(argc, argv, "1.2.3");
    listen(port);                                // 像普通变量一样用
    for (string_view path : flag::args()) { ... } // 位置参数
}
```

定义在哪里就能在哪里读，不用从 `main` 一路传下去。这是 Go 的 flag 包和 coost 的做法，也是 6.1 定下的需求。

**代价是全局选项对象在 `main` 之前登记**，这是「无启动开销」的第二个例外（第一个是 `TEST` 的自动注册）。已记进 `CLAUDE.md`。

`flag` 是**命名空间不是类模板**：类模板不带模板参数就没法写 `wavvix::flag::init`。

## 2. 和预期接口的三处不同

### 2.1 构造函数把主名字单列出来

计划：`value(T default_value, string_view help, std::initializer_list<const char*> names)`，主名字混在列表里。
改成：`value(const char* name, T default_value, const char* help, aliases = {})`。

三个理由：主名字是必须有的，混在列表里会让「空列表」变成运行时错误；`{"port", "p"}` 看不出哪个是主名（用法文本和错误消息要用主名）；`("port", 8080, "监听端口", {"p"})` 读起来就是「名字、默认值、说明、别名」。

### 2.2 补上 help_requested() / version_requested()

计划里 `parse` 返回 `result<void>` 而 `init` 退出进程，但**没有办法让 `parse` 的调用方知道 `--help` 来过**——它既不是错误也不该让库退出进程。这是计划的一个缺口，补了两个查询函数。

### 2.3 默认值存成文本

登记时把默认值转成文本存起来（`value<T>::default_text` 走 `to_string`）。两个收益：

- **`parse` 可以重复调用而结果确定**：每次先把默认值铺一遍，再处理这次的 argv。不这样做的话第二次 `parse` 会留着上次的值，而测试需要确定性（测试里有一条专门钉这个）。
- `usage()` 直接有默认值可以显示，不需要另存一份。

## 3. 四条解析规则（预期接口已定，这里只记实现）

| 规则 | 行为 | 不这样做会怎样 |
| --- | --- | --- |
| 1 | **位置参数之后继续解析选项**（GNU 风格重排） | `crop *.png --width=1024` 静默失效。这是 Go flag 包最常被抱怨的一点 |
| 2 | **布尔选项不吃下一个 token**，只接受 `--verbose` / `--verbose=true` | `crop --verbose a.png` 里的 `a.png` 会被当成 `--verbose` 的值 |
| 3 | `--` 之后全部算位置参数 | 没法处理以 `-` 开头的文件名 |
| 4 | 单独一个 `-` 算位置参数 | 违背「标准输入」的惯例 |

接受 `--port=8080`、`--port 8080`、`-p 8080`、`-p=8080`。**不支持粘连短选项 `-p8080`**（和 `-p -8080` 容易混），不支持合并 `-abc`。

**未知选项报错退出，不收进位置参数**——静默接受拼错的 `--widht` 是最常见的 CLI 坑。

## 4. 实现决定

### 4.1 登记表用函数内静态变量

```cpp
registry& table() {
    static registry instance;
    return instance;
}
```

不用文件级全局：全局选项对象在 `main` 之前构造，而文件级全局的初始化顺序**跨翻译单元是不确定的**，第一个构造的选项可能撞上还没初始化的 `vector`。函数内静态变量在第一次调用时才构造，没有这个问题。

### 4.2 登记期拒绝重名和保留名

写测试时发现两条静默的误用通道：

- 两个选项同名 → `find_by_name` 返回第一个，后登记的那个**永远读不到**。
- 别名是 `"h"` → 被内置的 `--help` 遮住，`-h` 永远走 help。

两者都在 `register_flag` 里打印诊断并 `std::abort()`，和测试框架处理重名测试的做法一致。也拒绝空名字和带前导 `-` 的名字。实测五种都触发：

```
"port" 和已登记的选项重名
"h"（--x 的别名） 是保留名，会被内置的 --help / --version 遮住
"help" 是保留名，会被内置的 --help / --version 遮住
名字 "--port" 不要带前导 '-'
有一个选项的名字或别名是空的
```

**这是「难以误用」优先于「实现简单」的一处**：多 20 行换掉一类只会在运行时表现为「我的选项怎么没生效」的 bug。

### 4.3 用法文本的类型标签是 ASCII

`<int>` / `<uint>` / `<num>` / `<str>`，不是 `<整数>` / `<字符串>`。

因为用法文本靠字节数对齐，而**按显示宽度对齐要内置 Unicode 表**——那是 `strings` 明确推后的功能（East Asian Width）。帮助文字在对齐列之后，所以它是中文不影响对齐。

### 4.4 错误消息在层边界补上选项名

`lexical_cast` 只知道「`"80x"` 不是合法整数」，只有 `flag` 这一层知道那是 `--port` 的值：

```
--port："80x" 不是合法整数
--retries："-1" 是负数，而目标类型是无符号的
```

这正是 `CLAUDE.md`「错误处理」那条约定的实例。

### 4.5 init 之前读取是终止，不是返回默认值

`get()` 在 `parse` 之前被调用时打印诊断并 `std::abort()`。那是编程错误（读一个还不存在的值），返回默认值会让它变成一个安静的逻辑 bug。

```
wavvix::flag: 在 init() / parse() 之前读取了 --port；选项的值要等命令行解析完才有意义
```

### 4.6 保留隐式转换，但选项不可拷贝

`operator const T&` 是 6.1 的需求（「像普通变量一样读取和输出」）。已知陷阱：`auto v = port;` 拷的是 `value<T>` 而不是 `T`。

**把拷贝构造删掉，所以这个陷阱是编译错误而不是静默的怪行为。** 头文件注释里写明要写 `auto v = port.get()`。coost 的宏方案没有这个陷阱（它定义出的 `FLG_name` 就是个真变量），这是用全局对象换来的代价。

### 4.7 没有 set_version / set_usage

版本号作为 `init` / `parse` 的参数传入。设置器的问题是**时序要求**：必须在 `init` 之前调用，忘了就静默失效，正是「零配置、零管理」和「没有意外」要挡的东西。

`version` 为空时不提供 `--version`，那时 `--version` 是未知选项（测试里钉住了）。

## 5. 实现验证

环境 Linux / GCC 14.2，`-Wall -Wextra -Wpedantic -Werror`，全程零警告。

### 5.1 构建与测试

134 个测试通过（新增 15 个）：五种类型 × 四种写法、四条解析规则各自的正反面、未知选项不进位置参数、缺值、五种转换失败、默认值在每次 parse 时恢复、`was_given`、`--help` / `--version` / version 为空、用法文本的七项内容、`set()` 的成功与两种失败、隐式转换在四种调用点、`args()` 的视图确实指向 argv（比对指针）、空命令行与 `argc == 0`。

头文件单独 `-fsyntax-only` 通过。`examples/flag.cpp` 是一个完整的切图工具 CLI，各个分支都跑过。

### 5.2 误用

六种误用都在独立子进程里验证过，release（`-O2 -DNDEBUG`）下全部打印诊断并 SIGABRT：重名、别名撞保留名、主名字是保留名、带前导 `-`、空名字、以及 `init` 之前读取。

### 5.3 一处用法上的粗糙

`usage()` 在任何 `parse` 之前调用时，程序名只能显示 `"program"`（它取自 `argv[0]`），而且不列 `--version`（版本号是 `parse` 的参数）。

示例里的「不带参数就打印用法」因此要先跑一次 `parse` 再调 `usage()`，并带注释说明。**没有改接口**：让 `usage()` 自己去摸 `/proc/self/exe` 之类是平台相关的额外依赖，而把版本号搬进设置器又会撞上 4.7 那个时序问题。

### 5.4 没覆盖

- **Clang、MSVC、macOS 都没跑过。** 本模块没有平台相关代码（唯一的间接依赖是 `fs::filename` 取程序名），所以风险比 `fs` 小得多。
- **`init` 的进程退出路径没有自动测试。** `init` 调 `std::exit`，测试里不能直接调；错误分支是手工在示例上验证的（退出码 2，用法打到 stderr）。`parse` 那条路径有完整测试。
- **多线程下 `set()` 和 `get()` 没有任何同步。** 登记表是全局可变状态，`set()` 在运行期被多个线程调用是数据竞争。目前的用法是「`main` 开头解析一次，之后只读」，这种用法下没问题；要支持运行期热加载配置就得加锁，到那时再说（第二程的配置文件模块会撞上这件事）。
- 选项数量很多时 `find_by_name` 是线性扫描。几十个选项无所谓，上百个再说。
