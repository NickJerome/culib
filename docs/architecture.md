# 实现分层

全库采用同一个原则：先把基本操作写清楚，再在其上组合功能和优化。判断一个模块是否简单，主要看理解它需要同时知道多少其他模块的细节，不按文件行数判断。

每一层拥有自己的状态，通过少量函数把能力交给上层。底层不读取上层的缓存、配置或调度状态；上层不直接修改底层的内部字段。不用虚基类、可插拔后端或模板框架来代替这些边界。只有一个直接实现的功能，保留直接实现。

## 全库的边界

| 部分 | 基础能力 | 在基础能力之上组合 | 需要隔离的优化或策略 |
| --- | --- | --- | --- |
| mem | 平台无关的内存页分配、释放、保留、提交 | slice 分配、页与块、对齐分配与公共 API | 尺寸分档、线程堆、延迟归还；不能反向渗入页分配 |
| 协程 | 寄存器切换、单个协程生命周期；栈向分配器要 | 就绪队列、挂起与唤醒、定时器 | 窃取、闲着的工作线程的唤醒、监控线程的名额交接、阻塞调用的后台线程；同步原语和网络只经挂起 / 唤醒接口，不认识这些 |
| 网络 | 地址编码、平台 socket 操作、I/O 完成 | 统一 `socket` 的监听、连接、字节流与报文收发 | 超时和等待由调度器提供；地址解析不依赖调度器 |
| 文件 | 平台文件句柄、文件信息、目录迭代 | 句柄式读写（`file` / `ofstream`）、复制、重命名与目录遍历 | 缓冲只放在需要它的流层；路径运算不碰磁盘 |
| 参数与配置 | 字符串视图、数值转换、文本解析 | 选项登记、命令行解析、配置对象 | 配置覆盖命令行属于两者之上的组合，不进入基础解析器 |
| 日志与终端 | 写入目标、终端能力 | 消息格式、级别过滤、文件轮转 | 过滤、格式化、目标生命周期各有清楚的归属 |
| 基础类型 | result、optional、string_view、字节缓冲 | 各模块直接使用 | 不为假想的泛型查询增加结构，不为简单函数制造层次 |
| 测试框架 | 用例登记、断言 | 用例执行与结果收集 | 参数解析和彩色展示使用库中已有能力 |

这些边界约束后续实现。现有功能和验证不能因为重构被悄悄删掉；没有消费者的兼容包装则直接去掉。

少代码的目标是减少独立概念、配置选择、重复状态和特殊路径。固定的合理默认值优先于可切换策略，提前返回优先于嵌套控制流；底层的资源所有者负责清理，使上层无需复制失败处理。不要靠压缩排版、移动文件或删掉必要检查凑行数。

## 当前边界

- 分配器的实现只有 `allocator/allocator.cpp` 一个文件，平台设施（锁、线程退出、fork、时钟）在 `allocator/native_*.cpp`，内存页操作在 `mem/pages`；分配器不直接调用系统内存 API。
- 协程栈向分配器要（`mem::aligned_alloc`），只有 debug 构建的保护页直接改 `mem/pages` 的页保护。
- `runtime/scheduler.cpp` 是运行时：工作线程和它们的就绪队列、窃取、闲着的工作线程、监控线程、定时器、普通线程上的等待和阻塞调用的后台线程；定时器的排序归 `timer_heap`。
- 配置解析、文件读取、应用 flags 已分开；路径字符串操作已脱离磁盘 I/O。同步原语只包含 park 接口（记下等待者、挂起、唤醒），网络只包含 `scheduler_adopt`、`scheduler_io` 和建套接字的 `io_open_socket`。I/O 引擎只持有不透明的 park_token 指针。

## 重构的验证方式

先使底层可以独立编译和测试，再让现有消费者改用它。逐步删掉旧路径，不保留两套实现。除了原有功能测试，还要核对依赖方向、共享状态和资源所有权确实减少；只搬文件不算完成。热路径比较同一编译配置下的生成代码或现有基准，不用性能猜测为复杂性辩护。

通用分配器最终要能替换进程的 `malloc/new`，因此它的底座直接调用系统虚拟内存 API；如果底座再调用被覆盖的 `malloc`，会递归进入自身。底座提供的是简单的分配/释放能力，平台实现分别使用 `mmap/munmap` 与 `VirtualAlloc/VirtualFree`，上层不需要知道这些差别。

## 已落实的独立单元

- `mem/pages`：分配器的 OS 内存页操作；协程栈只用它的 `protect` / `unprotect` 设 debug 构建的保护页。Linux 默认允许 overcommit 时，保留下来的地址空间直接可读写、提交是空操作、归还用 `MADV_DONTNEED`，全程不改映射（原因见 [分配器实现](mem-internals.md)）。
- `mem/allocator/native`：分配器唯一的锁、线程退出回调、fork 钩子、时钟和致命错误输出；`allocator.cpp` 不包含平台头文件。
- `runtime/timer_heap`：按时限排的最小堆，时限相同按放进来的次序；只管排序，不叫醒谁、不加锁，不访问工作线程或 I/O。调度器在定时器的锁里用它，到点以后决定谁进入就绪队列。
- `runtime/park.h`、`scheduler_io.h`：分别向同步原语和网络提供需要的接口。I/O 引擎无需知道 park_token 布局。
- `cli/config.cpp`：纯文本解析和配置查询；`config_file.cpp` 组合文件读取并补路径上下文；`config_flags.cpp` 组合命令行优先策略。没有新增公共包装接口。
- `fs/path.cpp`：路径运算只依赖字符串；`fs.cpp` 组合平台文件操作。flag 为提取程序名调用 filename 时不再连带需要磁盘 I/O 实现。
- `fs/file.h`：私有的打开、关闭、大小提示与单次读写操作。写满循环（`file::write`）、`copy_file` 与 `fs::ofstream` 的写出共用这一份底层原语，不再各写一份；临时句柄由 `defer` 清理，平台层不维护上层缓冲或写入计数。
- `src/net/net_socket.cpp`：统一 `socket` 的公共组合（惰性创建、协议与阶段校验、完整传输循环、报文收发）；建套接字、绑定、accept、connect 等平台操作在 `net_socket_posix.cpp` / `net_socket_win.cpp`，经私有的 `net_socket_detail.h` 相接。旧的 `net_tcp*` / `net_udp*` 分角色文件随合并删除，不留兼容层。

`layers_test` 直接编译这些底层文件，不链接 culib、不加入调度器、汇编、socket 或文件 I/O 后端。它验证配置与命令行解析、路径运算、定时器的任意取消与同截止时间排序，以及独立的页分配。若这些底层重新依赖上层，测试会在链接阶段失败，而不只是靠约定提醒。

定时堆保留每个等待项的位置，以便唤醒时立即移除。不能用延迟丢弃的 priority_queue 替代：token 在协程栈上，协程返回后悬垂项不能留在队列中。该结构保持现有 O(log n) 插入/取消；封装未增加虚调用、锁或单项分配。

网络地址编解码与解析原本就独立于调度器；TCP/UDP 的平台代码经 I/O 接口组合。基础类型与字符串工具原本也不依赖运行时，保留直接实现。日志输出列表已改为持有可移动的值对象，锁和配置标记也归于同一状态对象；文件句柄负责自身清理，轮转直接组合文件操作，无需额外策略框架。

运行时由一个 `runtime_state` 持有：工作线程、全局队列、闲着的工作线程名单、定时器堆、事件引擎和阻塞调用的后台线程都归它，第一次 `go()` 时建出来，之后不析构。每根工作线程只拥有自己的就绪队列（别的线程可以来拿）和当前协程；事件引擎和定时器整个进程各一份，协程在挂起点可能换到别的工作线程上继续。不在工作线程上的等待者（`main`、普通线程）睡在自己线程的等待器上，唤醒走同一套凭据。凭据的状态用一次比较交换在唤醒者和到点的一方之间定输赢，超时与唤醒同时发生时只有一方生效。协程第一次运行时才向分配器要栈，结束时还回去，运行时不缓存栈。

原来的 `vcpu_pool`、`remote_wake`、每根线程的栈池和线程退出回调都随这次改写删掉了：工作线程只由运行时创建，不再有「当前线程按需变成 vCPU」和与之配套的退出清理；栈的复用交给分配器。验证见[协程运行时](runtime.md#验证)。
