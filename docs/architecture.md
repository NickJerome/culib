# 实现分层

全库采用同一个原则：先把基本操作写清楚，再在其上组合功能和优化。判断一个模块是否简单，主要看理解它需要同时知道多少其他模块的细节，不按文件行数判断。

每一层拥有自己的状态，通过少量函数把能力交给上层。底层不读取上层的缓存、配置或调度状态；上层不直接修改底层的内部字段。不用虚基类、可插拔后端或模板框架来代替这些边界。只有一个直接实现的功能，保留直接实现。

## 全库的边界

| 部分 | 基础能力 | 在基础能力之上组合 | 需要隔离的优化或策略 |
| --- | --- | --- | --- |
| mem | 平台无关的内存页分配、释放、保留、提交 | 连续区域、块分配、对齐分配与公共 API | 尺寸分桶、线程缓存、延迟回收；不能反向渗入页分配 |
| 协程 | 栈内存、寄存器切换、单个协程生命周期 | 就绪队列、挂起与唤醒、定时器 | 多 vCPU 分发与跨线程通知；本地调度不需要理解工作池启动细节 |
| 网络 | 地址编码、平台 socket 操作、I/O 完成 | TCP / UDP 的连接与收发 | 超时和等待由调度器提供；地址解析不依赖调度器 |
| 文件 | 平台文件句柄、文件信息、目录迭代 | 整文件读写、复制与目录遍历 | 缓冲、批量操作只放在需要它们的组合层；路径运算不碰磁盘 |
| 参数与配置 | 字符串视图、数值转换、文本解析 | 选项登记、命令行解析、配置对象 | 配置覆盖命令行属于两者之上的组合，不进入基础解析器 |
| 日志与终端 | 写入目标、终端能力 | 消息格式、级别过滤、文件轮转 | 过滤、格式化、目标生命周期各有清楚的归属 |
| 基础类型 | result、optional、string_view、字节缓冲 | 各模块直接使用 | 不为假想的泛型查询增加结构，不为简单函数制造层次 |
| 测试框架 | 用例登记、断言 | 用例执行与结果收集 | 参数解析和彩色展示使用库中已有能力 |

这些是重构方向，不表示所有边界已经落实。现有功能和验证不能因为重构被悄悄删掉；没有消费者的兼容包装则直接去掉。

少代码的目标是减少独立概念、配置选择、重复状态和特殊路径。固定的合理默认值优先于可切换策略，提前返回优先于嵌套控制流；底层的资源所有者负责清理，使上层无需复制失败处理。不要靠压缩排版、移动文件或删掉必要检查凑行数。

## 当前主要问题

- `mem/allocator/internal.h` 同时定义页、arena、线程堆、指针定位、缓存快路径和全部模块接口；页、线程堆与缓存仍需进一步划清边界。
- 分配器与协程栈现已共用 `mem/pages`；元数据分配器已脱离 `allocator/internal.h`。
- `runtime/scheduler.cpp` 同时维护本地调度、定时器、远端完成事件和工作线程启动关闭；状态和生命周期需要进一步分开。
- 配置解析、文件读取、应用 flags 已分开；路径字符串操作已脱离磁盘 I/O。同步原语只包含 park 接口，网络只包含 scheduler_io 接口。I/O 引擎只持有不透明的 park_token 指针。

## 重构的验证方式

先使底层可以独立编译和测试，再让现有消费者改用它。逐步删掉旧路径，不保留两套实现。除了原有功能测试，还要核对依赖方向、共享状态和资源所有权确实减少；只搬文件不算完成。热路径比较同一编译配置下的生成代码或现有基准，不用性能猜测为复杂性辩护。

通用分配器最终要能替换进程的 `malloc/new`，因此它的底座直接调用系统虚拟内存 API；如果底座再调用被覆盖的 `malloc`，会递归进入自身。底座提供的是简单的分配/释放能力，平台实现分别使用 `mmap/munmap` 与 `VirtualAlloc/VirtualFree`，上层不需要知道这些差别。

## 已落实的独立单元

- `mem/pages`：分配器和协程栈共用 OS 内存页操作；`allocator/meta` 只在其上组合原生锁和 bump 分配。
- `runtime/wait_set`：拥有挂起计数、定时堆和同截止时间的顺序；只管理等待，不执行协程、不访问 vCPU 或 I/O。调度器处理通知和到期事件后决定谁进入就绪队列。
- `runtime/park.h`、`remote_wake.h`、`scheduler_io.h`：分别向同步原语、跨线程任务和网络提供需要的接口，删掉聚合的 scheduler_detail.h。I/O 引擎无需知道 park_token 布局。
- `cli/config.cpp`：纯文本解析和配置查询；`config_file.cpp` 组合文件读取并补路径上下文；`config_flags.cpp` 组合命令行优先策略。没有新增公共包装接口。
- `fs/path.cpp`：路径运算只依赖字符串；`fs.cpp` 组合平台文件操作。flag 为提取程序名调用 filename 时不再连带需要磁盘 I/O 实现。

`layers_test` 直接编译这些底层文件，不链接 culib、不加入调度器、汇编、socket 或文件 I/O 后端。它验证配置与命令行解析、路径运算、等待的任意取消与同截止时间排序，以及独立的页和元数据分配。若这些底层重新依赖上层，测试会在链接阶段失败，而不只是靠约定提醒。

定时堆保留每个等待项的位置，以便唤醒时立即移除。不能用延迟丢弃的 priority_queue 替代：token 在协程栈上，协程返回后悬垂项不能留在队列中。该结构保持现有 O(log n) 插入/取消；封装未增加虚调用、锁或单项分配。

网络地址编解码与解析原本就独立于调度器；TCP/UDP 的平台代码经 I/O 接口组合。基础类型与字符串工具原本也不依赖运行时，保留直接实现。日志输出列表已改为持有可移动的值对象，锁和配置标记也归于同一状态对象；文件句柄负责自身清理，轮转直接组合文件操作，无需额外策略框架。

本轮验证：MSVC x64 debug + WAVVIX_MEM_DEBUG 共 14 组测试通过，GCC 11.4 C++11 release 共 15 组通过，包含独立链接测试及已有配置、路径、同步、I/O、调度器和分配器回归。其后通过新增回收断言定位并修复了 Windows 后置析构的线程缓存滞留，详见 mem-internals.md。

工作池现在由 vCPU 的 `unique_ptr` 持有，池析构统一通知停止并 join 已启动的线程；启动失败和正常退出共用这一条清理路径。vCPU 使用值初始化，删除逐字段重复清零。跨线程唤醒准备失败直接返回空指针，包括 vCPU 本身无法分配的情况。

故障测试先记录一个 worker 实际需要的分配数，再逐点让两个 worker 的启动失败，覆盖第一个已启动、第二个启动失败的情况。失败不能执行或丢掉创建线程此前提交的任务，之后必须还能启动新池。旧路径在 vCPU 分配失败时直接 abort，新增测试已复现；修复后 Windows / Linux debug + L2 全套分别通过 14 / 15 组，日志无异常诊断。
