# 实现分层

全库采用同一个原则：先把基本操作写清楚，再在其上组合功能和优化。判断一个模块是否简单，主要看理解它需要同时知道多少其他模块的细节，不按文件行数判断。

每一层拥有自己的状态，通过少量函数把能力交给上层。底层不读取上层的缓存、配置或调度状态；上层不直接修改底层的内部字段。不用虚基类、可插拔后端或模板框架来代替这些边界。只有一个直接实现的功能，保留直接实现。

## 全库的边界

| 部分 | 基础能力 | 在基础能力之上组合 | 需要隔离的优化或策略 |
| --- | --- | --- | --- |
| mem | 平台无关的内存页分配、释放、保留、提交 | 连续区域、块分配、对齐分配与公共 API | 尺寸分桶、线程缓存、延迟回收；不能反向渗入页分配 |
| 协程 | 栈内存、寄存器切换、单个协程生命周期 | 就绪队列、挂起与唤醒、定时器 | 多 vCPU 分发与跨线程通知；本地调度不需要理解工作池启动细节 |
| 网络 | 地址编码、平台 socket 操作、I/O 完成 | TCP / UDP 的连接与收发 | 超时和等待由调度器提供；地址解析不依赖调度器 |
| 文件 | 平台文件句柄、文件信息、目录迭代 | 整文件读写、复制与目录遍历 | 缓冲、批量操作只放在需要它们的组合层；路径运算不碰磁盘 |
| 参数与配置 | 字符串视图、数值转换、文本解析 | 选项登记、命令行解析、配置对象 | 配置覆盖命令行属于两者之上的组合，不进入基础解析器 |
| 日志与终端 | 写入目标、终端能力 | 消息格式、级别过滤、文件轮转 | 过滤、格式化、目标生命周期各有清楚的归属 |
| 基础类型 | result、optional、string_view、字节缓冲 | 各模块直接使用 | 不为假想的泛型查询增加结构，不为简单函数制造层次 |
| 测试框架 | 用例登记、断言 | 用例执行与结果收集 | 参数解析和彩色展示使用库中已有能力 |

这些是重构方向，不表示所有边界已经落实。现有功能和验证不能因为重构被悄悄删掉；没有消费者的兼容包装则直接去掉。

## 当前主要问题

- `mem/allocator/internal.h` 同时定义页、arena、线程堆、指针定位、缓存快路径和全部模块接口；页、线程堆与缓存仍需进一步划清边界。
- 分配器与协程栈现已共用 `mem/pages`；元数据分配器已脱离 `allocator/internal.h`。
- `runtime/scheduler.cpp` 同时维护本地调度、定时器、远端完成事件和工作线程启动关闭；状态和生命周期需要进一步分开。
- 配置解析、从文件读取与应用到 flags 位于同一编译单元；同步原语通过调度器头间接取得整套 I/O 声明，依赖范围超过实际需要。

## 重构的验证方式

先使底层可以独立编译和测试，再让现有消费者改用它。逐步删掉旧路径，不保留两套实现。除了原有功能测试，还要核对依赖方向、共享状态和资源所有权确实减少；只搬文件不算完成。热路径比较同一编译配置下的生成代码或现有基准，不用性能猜测为复杂性辩护。

通用分配器最终要能替换进程的 `malloc/new`，因此它的底座直接调用系统虚拟内存 API；如果底座再调用被覆盖的 `malloc`，会递归进入自身。底座提供的是简单的分配/释放能力，平台实现分别使用 `mmap/munmap` 与 `VirtualAlloc/VirtualFree`，上层不需要知道这些差别。
