# mesh 应用层（开发中）

这个 xmake 工程单独依赖 libsodium 1.0.22，根工程的 `culib` 静态库不引入该依赖。进入 `apps/mesh` 后运行 `xmake f -P . -m debug -y`、`xmake test -P .`，即可构建并测试目前的加密候选与数据包。

每个节点持有 X25519 公私钥，信令层必须从配置中取得并固定对端公钥。`seal_offer()` 先用 culib 的 `punch_offer` 格式编码候选，再用 libsodium `crypto_box_easy` 加密并认证；信令中继只能看到用于转发的发送者、收件者公钥。`offer_receiver` 检查收件者和允许的发送者、认证密文、消息时间及近期 nonce，接受后才解码候选。消息有效期为 60 秒，允许发送方时钟快 30 秒。接收者必须在其 `identity` 生命周期内使用；同一接收者对象的重复消息会被拒绝。

`traffic_session::create()` 用双方固定的公钥与同一个 16 字节会话 ID 派生两个方向不同的密钥。`seal()` / `open()` 写入调用方缓冲区，不在逐包路径上分配内存；XChaCha20-Poly1305 校验数据及包头，接收端允许 64 个序号的乱序窗口并拒绝重复包。会话 ID 必须由安全随机源为每次连接重新生成，双方通过已认证的候选消息取得它。单个 UDP 包最多 65507 字节，其中 28 字节用于包头和认证码，超长 IP 包尚无分片机制。

候选消息格式为 `CME1`（4 字节）、发送者公钥（32）、收件者公钥（32）、随机 nonce（24）、`crypto_box` 密文及认证码。密文内含 8 字节大端 Unix 秒数和 `punch_offer`，最大 873 字节。数据消息格式为 `CMD1`（4 字节）、8 字节大端序号、密文及 16 字节认证码。私钥与会话密钥在移动或析构时清零；身份目前只在进程内生成，没有持久化或密钥轮换。固定 X25519 身份密钥派生的数据密钥不提供前向保密；重建相同会话 ID 的对象也会重置重放窗口，所以节点协议必须保证会话 ID 唯一且不复用。这些只是协议构件；完整握手、身份文件、保活、NAT 映射变化恢复和虚拟网卡转发仍未实现，不能作为可部署 mesh 节点使用。
