# mesh 应用层（开发中）

这个 xmake 工程单独依赖 libsodium 1.0.22，根工程的 `culib` 静态库不引入该依赖。进入 `apps/mesh` 后运行 `xmake f -P . -m debug -y`、`xmake test -P .`，即可构建并测试目前的加密候选消息。

每个节点持有 X25519 公私钥，信令层必须从配置中取得并固定对端公钥。`seal_offer()` 先用 culib 的 `punch_offer` 格式编码候选，再用 libsodium `crypto_box_easy` 加密并认证；信令中继只能看到用于转发的发送者、收件者公钥。`offer_receiver` 检查收件者和允许的发送者、认证密文、消息时间及近期 nonce，接受后才解码候选。消息有效期为 60 秒，允许发送方时钟快 30 秒。接收者必须在其 `identity` 生命周期内使用；同一接收者对象的重复消息会被拒绝。

当前消息格式为 `CME1`（4 字节）、发送者公钥（32）、收件者公钥（32）、随机 nonce（24）、`crypto_box` 密文及认证码。密文内含 8 字节大端 Unix 秒数和 `punch_offer`，最大 873 字节。私钥只在进程内生成，移动或析构时清零；还没有持久化、密钥轮换或节点配置。静态密钥的 `crypto_box` 不提供前向保密，近期 nonce 缓存也不是跨进程的持久重放数据库。这一层只保护候选消息；数据包加密、完整握手、身份文件、保活、NAT 映射变化恢复和虚拟网卡转发仍未实现，不能作为可部署 mesh 节点使用。
